# Runbook — Set a tenant's plan (sales-led, DECISION-031)

**When:** a customer has agreed to a paid plan (monthly or annual) and paid or been invoiced.
Only Free is self-serve; no trials exist. Every paid plan is applied by a super admin.

**What it changes:** `POST /api/v1/billing/upgrade` (api-gateway) updates `tenants.plan` and
`tenant_subscriptions` (`plan`, `status='active'`, `previous_plan`) in one transaction, then
invalidates the plan cache. Quotas and feature gates follow `tenants.plan` from then on.
Downgrades are refused if current usage exceeds the target plan's limits (users, IOCs, etc.).

## Steps
1. Find the tenant id. In Command Center → Clients, or read-only on the VPS:
   ```sql
   BEGIN READ ONLY; SELECT id, slug, plan FROM tenants WHERE slug = '<slug>'; ROLLBACK;
   ```
2. Sign in to intelwatch.in as a **super admin**. Copy the access token from the browser: DevTools → Application → Local Storage → `etip_auth` → `accessToken`. It's valid for about 15 minutes.
3. Apply the plan. `targetPlan` is one of `free | starter | pro | enterprise`. `pro` is the Teams plan.
   ```bash
   curl -sS -X POST https://intelwatch.in/api/v1/billing/upgrade \
     -H "Authorization: Bearer $TOKEN" \
     -H "x-tenant-id: <tenant-uuid>" \
     -H "Content-Type: application/json" \
     -d '{"targetPlan":"starter"}'
   ```
   Expected: `200` with the new plan. `403` means the token isn't a super admin. `422 DOWNGRADE_EXCEEDS_LIMITS` means usage exceeds the target plan's limits. `400 ALREADY_ON_PLAN` means the tenant is already on that plan.
4. Verify: the tenant's Billing & Plans tab shows the new plan. Or, read-only:
   `SELECT plan FROM tenants WHERE id = '<tenant-uuid>'` and `SELECT plan, status FROM tenant_subscriptions WHERE tenant_id = '<tenant-uuid>'`.
5. Record the deal (plan, monthly or annual, invoice number) wherever sales records live. Billing-service invoices aren't generated by this path.

## Notes
- Never edit `tenants.plan` with raw SQL. It skips the subscription row, the downgrade checks and the plan-cache invalidation.
- The Command Center "Clients" plan selector writes to admin-service's in-memory registry (DECISION-013). It does **not** change the real plan. Use this runbook until that UI is wired to this endpoint.
- The `intelwatch-system` tenant (super admin / break-glass) stays on `enterprise`. Don't change it.
